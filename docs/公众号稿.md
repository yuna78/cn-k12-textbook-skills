## 正文

### 我做了什么

三个 skill，串成一条线：

```
fetch-pdf  →  pdf-to-kb  →  ask-kb
拿 PDF        拆成知识       带出处答题
```

仓库：`cn-k12-textbook-skills`（中国中小学教材 AI 技能系列），MIT 开源。

### 为什么做这个

孩子上初中，教材主要来自**国家中小学智慧教育平台**（教育部那个免费电子课本），
加上老师发的讲义、讲评、答案册，全在电脑里。我想让 AI 帮我查"这个知识点书上哪一页讲的"，试了几次都不行：

1. **下不下来**：国家中小学智慧教育平台的电子课本只能在线翻，没有下载按钮，链接复制出来一探 401。
2. **读不动**：一本 300 页的教材塞不进上下文；OCR 成文本后也没页码，问细节只能含糊。
3. **会编**：普通 RAG 检索到相邻内容就拿常识补全，答案看着像，对不上原文。

所以拆成三个 skill，一个管一段。

### 三个 skill 分别干什么

#### 1. `fetch-pdf`：把 PDF 拿下来

```bash
# 直链能下就直接下（断点续传 + 三重校验）
python3 skills/fetch-pdf/scripts/fetch.py "<url>" -o books/book.pdf --resume
```

- 页面没下载按钮 → 先解析公开的元数据拿真实地址，再取 1KB 探一下：
  **200/206 就是公开的，直接下；401 才说明要登录**
- 要登录的资源：在**浏览器页面内**取数，凭证不出浏览器、不导出、不落盘
- 防半截文件：断点续传 + 查 `%PDF` 头、`%%EOF` 尾、字节数

实测：故意造一个 60% 的残片文件，续传后字节数和 md5 跟原文件完全一致。

#### 2. `pdf-to-kb`：拆成能引用的知识

```bash
python3 skills/pdf-to-kb/scripts/extract.py books/book.pdf --out work/
python3 skills/pdf-to-kb/scripts/segment.py --work work/ --manifest book.manifest.json --out kb/
python3 skills/pdf-to-kb/scripts/figures.py --pdf books/book.pdf --work work/ --kb kb/
python3 skills/pdf-to-kb/scripts/build.py --kb kb/ --verify
```

关键只有一个：**按页抽，页码留着**。

```markdown
---
id: 化学九上-第四单元
pdf_pages: 88-113        # PDF 物理页
source_pages: 78-103     # 书上印刷页
---

<!-- p.78 (pdf 88) -->
（这一页的正文）
```

没有 `<!-- p.78 -->` 这行，后面所有"出处"都是假的。

另外两件事：

- **扫描件自动 OCR**（很多平台教材就是页图拼的，没文字层），每个单元标质量等级，
  `low` 的回答时提醒"OCR 可能有误，请对纸质书"
- **图单独索引**：图里的字 OCR 抓不到，但"图12-4-1 → 第 89 页 → 原图"这条路能走通，
  被问到图时给原图，不猜

#### 3. `ask-kb`：只答有出处的

```bash
K="python3 skills/ask-kb/scripts/kb.py --kb kb"
$K judge  "水的净化有哪几种方法"     # ① 先判：可靠 / 存疑 / 无
$K search "净化 过滤 蒸馏" --top 6   # ② 检索：单元 + 页码 + 原文
$K verify drafts/answer.md --question "水的净化有哪几种方法"   # ③ 硬校验
```

跟常见方案比，只有一点不一样：**不靠提示词让它别编，靠程序卡它**。

| judge 结果 | 允许怎么答 |
|---|---|
| 可靠 | 正常答 + 每条 `[引] 单元 @p页 :: 原文` + verify 通过 |
| 存疑 | 列候选、逐条给页码，不许下单一结论 |
| 无 | 只能说"本地资料没有"，给常识必须标 `⚠️ 非本地资料` |

verify 查得很死：引文去掉空白标点后，必须是那一页原文的**子串**，改一个字都过不去。
判"可靠"但 verify 不过 → **以 verify 为准，拒答**。

### 怎么装（Claude / Codex / WorkBuddy 都能用）

脚本是纯 CLI，**任何能跑 bash 的 agent 都能用**，不装 skill 也行。三种接法：

| 环境 | 接法 |
|---|---|
| **Claude Code** | 把 `skills/*` 放进 `~/.claude/skills/`（用户级）或项目 `.claude/skills/`，它会自动识别 `SKILL.md` |
| **Codex**（OpenAI Codex CLI） | 把 `SKILL.md` 里"命令怎么跑"那一段写进仓库根目录的 `AGENTS.md`，或作为自定义指令加载；脚本照常 `python3` 调用 |
| **WorkBuddy** | 它的技能就是 `<skill-name>/SKILL.md` 结构，和本仓库一样；把 `skills/` 下三个目录拷进技能目录即可 |
| **其它** | 直接当命令行工具用，三条命令串起来就是流水线 |

```bash
git clone <repo> cn-k12-textbook-skills
cd cn-k12-textbook-skills
cp -r skills/* ~/.claude/skills/     # Claude Code 用户级
```

### 效果（实测，发布前重跑）

我自己的库：609 个知识单元、563 条图索引（一套初中教材 + 老师资料）。

| 指标 | 结果 |
|---|---|
| 问到对的地方（Recall@1） | 97.4% |
| 库里有却判"没有"（误拒） | 0% |
| 库里没有时老实说没有（拒答准确率） | 100% |
| 引文能落到原文（引用闸门） | 12/12 |

最后一行是我最看重的：**它现在会说"这个书里没有"**。

### 踩过的坑（这部分最有用）

1. **中文 URL 不编码直接报错**。平台文件名带中文，`urllib` 抛 `'ascii' codec can't encode`，
   必须对 path 做百分号编码。
2. **`pdftotext -layout` 会把汉字拆成"汉 谟 拉 比"**，二元组分词全断，检索莫名其妙查不到。
   分词前先去掉汉字之间的空格。
3. **judge 用绝对分数阈值会失准**，换一本书就得重调。改成"归一化相关度"（top1 / 该问题理论最高分）。
4. **覆盖率不能算疑问词**。"是什么性质"里的"什么""质的"会把正确回答判成答非所问，只按实词算。
5. **索引里漏存源文件路径**，按页渲染直接找不到 PDF。索引和 md 两边都要能兜底。

### 最后说清边界

这套东西保证的是"**引文真实存在于原文**"，不保证"原文本身是对的"。错题答案、OCR 误字，
还是要人看一眼。工具的作用是把"翻书找页码"这件苦活接过去，判断留给人。

- 只处理你自己提供、且你有权访问的文件
- 不绕过付费墙、不破解 DRM、不批量爬站
- 仓库里不含任何教材原文（版权原因，`.gitignore` 直接排除 `*.pdf`）
